## 1. BIOS 设置（重启时连按 F2；如需高级项先按 F7）

| 设置项 | 目标值 | 重要性 | 本机实测（2026-10-12 修正） |
|---|---|---|---|
| Secure Boot | **Off**（ASUS 若有 “OS Type” 选 **Other OS**） | 必须 | ✅ 已关 |
| CSM / Legacy Boot | **Off** | 必须 | 待确认（ASUS 消费本多无此项） |
| **Above 4G Decoding** | On | 必须 | ✅ **已经是开的，无需操作** |
| **Resizable BAR / Re-Size BAR** | On | 必须 | ✅ **已经是开的，且 BIOS 故意不显示** |
| Fast Boot（BIOS 里的，不是 Windows 快速启动） | Off | 建议 | 有就关，没有跳过 |
| XHCI Hand-off（及 EHCI Hand-off） | On | 建议 | 有就开，没有跳过 |
| IOMMU | **Off** | 建议（非必需） | 有这项就关；没有就跳过 |

**⚠️ 关于 Resizable BAR：不要再在 BIOS 里找了**（2026-10-12 修正）
- **华硕官方说明**（[FAQ 1049974](https://rog.asus.com/hk/support/faq/1049974/)）：Intel 11 代以上 / **AMD Ryzen 5000 系列以上**的华硕笔记本，
  Resizable BAR **默认即为开启**，且 **"BIOS設定頁面中不會顯示此選項"**。本机是 Ryzen 7 8845H（8000 系）→ 适用。
- **实测确认已开启**：`nvidia-smi -q` → `BAR1 Memory Usage / Total = 8192 MiB`（8GB，Used 8163 MiB）。
  未开 ReBAR 的卡只会暴露 256 MiB。
- **之前的扫描报告 "Resizable BAR: Disabled" 是误报**：Hardware Sniffer 的判定条件是注册表
  `KMD_RebarControlMode == 1`（`windows.py:287`），而本机 RTX 4050 的子键里**该值不存在**（新驱动 617.14 不写它），
  于是被判为 Disabled。
- **Above 4G Decoding 同样已开启**：8GB 的 BAR1 在 4GB 以下无法放置，能存在即证明 64 位 MMIO 窗口已分配。
- 想自己复核的话：右键桌面 → NVIDIA 控制面板 → 帮助 → 系统信息 → 看 **Resizable BAR** 一行。

**所以这两项 "must" 在本机已经满足，BIOS 里没有必须改的东西。** 进去确认一下 Secure Boot 是关的，
有 IOMMU 就关掉（建议项），然后 Save & Exit 即可。

**兜底开关**：万一 macOS 在极早期卡死，可以在 `Kernel → Quirks` 把 `DisableIoMapper` 设为 `True`
（本机当前为 `False`，因为 1401 只对 Intel Core Ultra 强制打开它）。改完需要重建 EFI 并重写 U 盘，我可以一分钟做完。

## 2. 安装 macOS

### 2.1 从 U 盘启动
1. U 盘插着，重启，开机时连按 **Esc**（ASUS 的启动菜单热键，部分机型 F8）→ 选 `UEFI: SMI SM3350`。
2. 进入 OpenCore 菜单 → 选末尾带 **`(dmg)`** 的安装项（macOS Base System）。
3. 第一次启动是**满屏文字（verbose）**，这是有意为之（boot-args 带 `-v`），方便排错，不是故障。

**应急：开机菜单里看不到这块 U 盘**
它走的是 UEFI 可移动介质约定路径（`\EFI\BOOT\BOOTX64.EFI`），不是 ESP 分区。
绝大多数固件（含 ASUS）都支持，但个别固件只识别类型为 `0xEF` 的分区。真遇到就告诉我，
我把这个 FAT32 分区的 MBR 类型字节从 `0x0C` 改成 `0xEF` 即可（不影响盘内文件，不用重写）。
也可以先在 BIOS 里试着用「Boot from file / 从文件启动」手动指到 `\EFI\BOOT\BOOTX64.EFI`。

### 2.2 ⚠️ 分区：不要点「抹掉」整个磁盘！
1401 的手册是按「macOS 独占整块硬盘」写的 —— 它会让你选中**整个磁盘**然后抹掉。
**你的 macOS 要和 Windows 共用这块 WD SN740，抹整盘 = Windows 全没了。**

正确做法（非破坏性）：
1. 打开 **磁盘工具 Disk Utility** → 菜单 **显示 → 显示所有设备**。
2. 左侧选中**整块磁盘**（`WD PC SN740 …512G`，不是 `C:` 卷）。
3. 点上方的 **分区 (Partition)** 按钮 → 在饼图里选中那块 **约 128GB 的空白区域** → 点 **`+`**。
4. 新分区：格式选 **APFS**，名称填 `Macintosh HD`（或任意名），大小用满那块空白 → **应用**。

   这样只会往 C: 与 WinRE 恢复分区之间的空闲空间里插入一个 APFS 容器，**不会动 Windows 分区**。
   若图形界面不给力，可在安装器里开 **终端**：`diskutil list` 看盘，再用 `diskutil addPartition` 系列命令
   （需要的话把 `diskutil list` 的输出发我，我给你确切命令，别自己猜）。

**本机分区布局（Windows 侧实测，供你在安装器里核对）**

| 分区 | 内容 | 起止 | 大小 |
|---|---|---|---|
| disk0s1 | EFI 系统分区 | 1 MiB – 201 MiB | 200 MB |
| disk0s2 | Microsoft Reserved (MSR) | 201 MiB – 217 MiB | 16 MB |
| **disk0s3** | **Windows C: (NTFS)** | 217 MiB – 348.01 GiB | 347.80 GiB |
| ← **空闲** → | **给 macOS 的区域** | **348.01 – 476.01 GiB** | **≈128.0 GiB** |
| disk0s4 | Windows 恢复 (WinRE) | 476.01 – 476.94 GiB | 949 MB |

`diskutil list` 里你会看到同样的顺序（EFI / Microsoft Reserved / Microsoft Basic Data / Windows Recovery），
**空闲空间夹在第 3 和第 4 个分区之间**。终端做法（先看清楚再动手，编号不对就别执行）：

```bash
diskutil list                     # 核对：disk0s3 = Microsoft Basic Data，disk0s4 = Windows Recovery
diskutil addPartition disk0s3 APFS "Macintosh HD" 128g   # 在 disk0s3 之后的空闲空间建 APFS
diskutil list                     # 复查：新分区应出现，Windows 分区大小未变
```

> 关键判断：执行完 `diskutil list`，**C: 那个分区的大小必须还是 347.8 GiB 左右**。如果它变小了，
> 说明操作吃掉了 Windows 的空间 —— 立刻停手，别再点「重新安装」。

5. 退出磁盘工具 → **重新安装 macOS** → 选择刚建的 `Macintosh HD`。

### 2.3 安装过程必须联网（已解决，见下）

「重新安装 macOS」这一步会**从 Apple 服务器下载完整系统**（约 10GB+）。本机的两种内置网卡都用不了：
- **MediaTek MT7922（无线）**：macOS 无驱动，而且 `SSDT-Disable_Network_GPP6` 会在 macOS 下把它的 `_DSM`
  伪造成 `class-code=FFFFFFFF` / `vendor-id=FFFF`，**主动让 macOS 忽略它**；
- **无 RJ45 网口**。

#### 2.3.1 ❌ 你插的那块 2.5G 有线网卡（RTL8156）不能用（2026-10-12 实测）

设备：`USB\VID_0BDA&PID_8156` —— Realtek **RTL8156** 2.5GbE。

| 证据 | 说明 |
|---|---|
| `CompatibleIds = USB\COMPAT_VID_0BDA&Class_FF&SubClass_FF&Prot_00` | 设备以**厂商自定义类（0xFF）**枚举，**不是 CDC-ECM（class 02）**。macOS 的通用 USB 网卡驱动只认 CDC-ECM，所以不会自动绑定 |
| Realtek 官方另有 macOS 驱动（**USB FE/GBE/2.5G/5G, macOS 11~26**） | 存在官方驱动本身就说明 macOS **没有**原生支持 2.5G USB 网卡 |
| macOS 只自带 `AppleUSBRealtek8153Patcher` | 覆盖 **RTL8153**（GbE）；**RTL8156 不在其列** |

结论：这块卡在 Windows 上正常，但**在 macOS 安装器里完全没网**，也无法在安装前安装厂商 kext。

#### 2.3.2 ✅ 已为你启用：安卓手机 USB 共享网络（免费）

我确认了 OpCore-Simplify 的驱动库里有 **HoRNDIS**（`TomHeaven/HoRNDIS` 维护分支，rel9.3_2），
解剖后确认它可用：

| 项 | 值 |
|---|---|
| 版本 / 架构 | 9.3；**FAT universal，含 x86_64** ✅（社区说的"不兼容"只针对 Apple Silicon） |
| 依赖 | 仅 Apple 原生 IOKit（`IONetworkingFamily`、`IOUSBHostFamily`）→ **可独立注入** |
| 匹配签名 | `0xE0/0x01/0x03`（标准 RNDIS）、`0xEF/0x04/0x01`、`0x02/0x02/0xFF` —— 正是 Android 的 RNDIS |
| 签名 | 带 `_CodeSignature` |

**已把这个 kext 注入到 U 盘的 `EFI/OC/Kexts/HoRNDIS.kext`**，并写入 `config.plist` 的 `Kernel → Add`（第 26 项，
Enabled=true），重新构建后 **ocvalidate 0 issues**、137 个 EFI 文件与构建逐字节一致。

**用法**：安卓手机用数据线插到电脑 → 打开手机「**USB 网络共享**」→ 安装器里就应当出现网络。
（`AMD USB 3.x` 控制器 + HoRNDIS 匹配的是 USB 接口描述符，与手机型号无关。）

#### 2.3.3 备选方案

1. **RTL8153 芯片的 USB/Type-C 转 RJ45 网卡**（几十元）—— macOS 自带 `AppleUSBRealtek8153Patcher`，
   安装器里即插即用。**这是最稳的兜底**，HoRNDIS 万一不灵就买它。
2. **iPhone 的 USB 共享网络**—— macOS 原生支持，不需要任何 kext。
3. **换 M.2 无线网卡**为 macOS 原生型号（如 BCM94360NG）。注意：换完必须**删掉
   `SSDT-Disable_Network_GPP6.aml`** 并从 config 的 ACPI→Add 移除，否则新网卡一样被伪造 ID 屏蔽——我可以帮你重建 EFI。
4. **借一台 Mac 做全离线安装盘**（见附录 A 方案 A）—— 完全不需要联网。

### 2.4 安装过程中的重启
- 系统会**重启多次**。每次都要再次从 U 盘启动，在 OpenCore 里选 **macOS Installer**，
  直到它变成 **Macintosh HD** 为止。
- **U 盘一直插着**：目前它是你这台机器启动 macOS 的唯一途径。

## 3. 安装 NVIDIA 驱动（进桌面之后）

1. 在 U 盘的 `NullMoth` 文件夹里：
   - 解压 `1401-Mac-1.14.2.zip`，运行里面的 **1401.app**（驱动包已经在 U 盘里，不用再下载）。
2. 按 App 的步骤走：它会检查/修改 OpenCore 配置（把 BAR 改成 `13`/`-1`、屏蔽 `IONDRVSupport`）、

4. 重启。第一次带驱动启动会在 “PCI configuration end” **卡最多 1 分钟**，是正常的。
5. 首次会要求在 **系统设置 → 隐私与安全性** 里「允许」这些扩展 → 允许后**再重启一次**。

## 附录 A：能不能"离线"安装？（2026-10-12 查证）

**结论：Windows 单机做不到全离线安装；必须先拿到恢复镜像，安装过程仍需联网。**

依据（三条独立来源一致）：
1. **Dortania 官方 Windows 教程**只提供 `macrecovery.py`——它给的是**恢复镜像**，不是完整安装镜像。
2. **Hackintosh-Forum 词条**《Recoveryimage-Methode bei Windows als Hostbetriebssystem - und Fullinstaller bei anderen》：
   标题即结论——**Windows 作宿主机只能用恢复镜像法**；Fullinstaller 需要**已有一台 macOS/黑苹果机器**才拿得到。
3. **Gilberto-Mascena 的 Windows 教程**原文：*"This process will not use a full macOS image, but rather a recovery image.
   It will download everything from Apple's servers that will be used to install macOS on your PC."* 以及
   *"Make sure your EFI is configured correctly to allow internet access **this is a requirement**, as the recovery
   will download macOS in real time from Apple's servers."*

**1401 自己的"离线"选项也只到这一步**：`p1401/apple.py` 的 `local_image()` 接受你预先放好的
`BaseSystem.dmg` + `BaseSystem.chunklist`（省掉那 850MB 下载），注释写着 *"one user asked for an offline
installer: this is it"*——但它不构建完整安装器，`/「重新安装 macOS」`阶段照样从 Apple 拉系统。

**技术原因**：`createinstallmedia` 是 macOS 专有工具；Big Sur 起安装盘必须是 **APFS**，而 Windows 无法写 APFS。
TransMac / balenaEtcher 那一代工具只能处理 Big Sur 之前的 HFS+ 安装盘。

**能实现全离线的四种办法**

| 办法 | 需要什么 | 说明 |
|---|---|---|
| **A. 借一台 Mac 30 分钟** | 任意 Mac + 16GB U 盘 | 在 Mac 上跑 `createinstallmedia` 生成完整离线安装盘，再把我们**已校验的 `1401\build\EFI`** 拷进该盘的 EFI 分区即可。**这是唯一真正全离线的路** |
| **B. USB 网卡** | RTL8153 芯片网卡（几十元） | 按现有方案联网安装，最省事 |
| **C. 换无线网卡** | BCM94360NG 等 macOS 原生卡 | 换完**必须删掉 `SSDT-Disable_Network_GPP6.aml`** 并从 config 的 ACPI→Add 移除，我帮你重建 EFI |
| **D. 借 Mac 装到外置 SSD** | 任意 Mac + USB 硬盘盒 | macOS 安装可移植；装完插到本机用 OpenCore 启动。无需联网 |

> 办法 A 的 Mac 端命令：
> ```bash
> sudo /Applications/Install\ macOS\ Sequoia.app/Contents/Resources/createinstallmedia --volume /Volumes/MyUSB
> diskutil list                    # 找到该 U 盘的 EFI 分区（通常 disk2s1）
> diskutil mount disk2s1           # 挂载后把 1401\build\EFI 整个拷进去（与 /EFI/BOOT、/EFI/OC 同级）
> ```
> 注意：`createinstallmedia` 会清空该 U 盘，且 Mac 上需先下载完整安装器（约 13–15GB）。

**三项诚实的未决项（不致命，但要知道）**

1. **触控板**：本机是 ASUS I2C HID（`ASUF1208`），走 AMD 的 I2C/GPIO 控制器。VoodooI2C 对 AMD GPIO 的支持
   是这套组合里最没把握的一环。构建里没有专门的 GPIO 引脚 SSDT，只靠 `-vi2c-force-polling`。
   **键盘是 PS/2（MSFT0001）→ VoodooPS2，基本可预期能用**；触控板不行就插 USB 鼠标。
2. **`layout-id` 用的是整数（56）**，而 Dortania 规范写的是 Data。OpCore-Simplify 一直这么写。
   若进系统后没声音：AppleALC 源码 `kern_alc.cpp:278` 里 **`alcid=` 启动参数优先级最高**，
   直接在 boot-args 加 `alcid=56` 即可绕过属性类型问题（或者把 layout-id 改成 Data）。
3. **没有 CPU 温度/频率监控**：未装 `SMCAMDProcessor` + `AMDRyzenCPUPowerManagement`（Zen 4 上不稳，属谨慎取舍）。
   `DummyPowerManagement=True` 也意味着走的是 AMD 标准做法。USB 端口映射仍是 `mapping_required`，
   装完系统后用 1401 Mac App 生成 `UTBMap.kext`。
