### 1.2 技术原理（`docs/HOW-IT-WORKS.md`）

```
Metal App / WindowServer / Core Image / MPS
   └─► NVMTLDriver.bundle            金属驱动插件（Apple Metal 加载）
        └─► translator：Apple AIR → SPIR-V（基于 metal2vulkan）
             └─► NVK：Mesa 的 Vulkan 驱动 + NAK 编译器（打到 Mesa 17ca6174 的补丁）
                  └─► NVRM.kext：NVIDIA 官方开源内核模块 r610 移植到 XNU
                       └─► GSP 固件 610.57.04 ──► GPU
显示侧：NVRMFB.kext(IOFramebuffer) + NVAccel.kext(IOAccelerator) + NVRMAGDC.kext(显示策略)
```

本质不是“重写 NVIDIA 驱动”，而是**把 Apple 的中间着色语言翻译成 SPIR-V 后喂给 Mesa 的 NVK**，内核态跑 NVIDIA 自己的开源模块。这也是它能对新卡（RTX 50）生效的原因。

### 1.3 它要求的系统条件（`README.md` §Wiring into an existing OpenCore setup）

| 项 | 值 | 说明 |
|---|---|---|
| `csr-active-config` | `430A0000` | **SIP 必须放宽**（未签名 kext） |
| `boot-args` | `amfi_get_out_of_my_way=0x1 amfi=0x80 ...` | **绕过 Apple 的 AMFI 签名校验** |
| `SecureBootModel` | `Disabled` | Apple 安全启动必须关闭 |
| `ResizeGpuBars` / `ResizeAppleGpuBars` | `13` / `-1` | 8GB BAR1（安装器阶段要反过来设） |
| `Kernel → Block` | 排除 `IONDRVSupport` | 否则固件帧缓冲抢走 display 0 |
| BIOS | Above 4G Decoding 开、CSM 关 | |
| SMBIOS | 需能跑 macOS 15 且有独显的机型（1401 用 `iMacPro1,1`，Tahoe 用 `MacPro7,1`） | |

> ⚠️ 这意味着装完后系统安全性显著降级（SIP 放宽 + AMFI 旁路 + 安全启动关闭）。**不适合当处理敏感数据的主力机。**

### 1.4 支持范围与“含金量”（`docs/CARD-SUPPORT.md`）

驱动在设备表里带 235 个 NVIDIA PCI ID（Turing 及更新），但**物理验证只有一张 RTX 5060 桌面卡**：

| 家族 | 设备表覆盖 | 物理验证 |
|---|---|---|
| Turing (GTX16/RTX20) | ✅ | Pending |
| Ampere (RTX30) | ✅ | Pending |
| **Ada (RTX40，含本机 RTX 4050 Laptop)** | ✅ | **Pending** |
| Blackwell (RTX50) | ✅ | RTX 5060 自动化；5070/5080 用户反馈可用 |

文档原话：“device-table coverage is not runtime qualification”（进了设备表 ≠ 真能跑）。Pascal/Maxwell/Kepler 完全不在内。

### 1.5 已知未解决项（`docs/TROUBLESHOOTING.md` + v1.14.x release notes 的 "Still open"）

- **HDMI / DisplayPort 音频**（NVIDIA 卡的 HDAU）完全不工作
- Chrome 的 WebGL（Safari 可用）
- 运行中热插拔新显示器
- **高刷屏闪烁 / 黑屏**（>60Hz、DP、多屏）——1.14 已发 DSC 压缩设置，仍未彻底解决
- 笔记本内屏亮度需 `nvrmacpibl=1` 试验参数
- “无 MUX 的 Optimus 笔记本内屏”问题（1.12 只解决了 Intel 核显驱动内屏的情形）
- AMD/Intel 核显加速（NMXGPU 测试驱动）**代码写完了但从未在真 AMD GPU 上跑过**（`RELEASE-1.14.0.md` §AMD and Intel GPUs）

### 1.6 值得注意的实证（GitHub issues 真实案例）

| Issue | 机器 | 结果 |
|---|---|---|

## 三、逐项可行性判定

| 维度 | 判定 | 说明 |
|---|---|---|
| CPU 能否跑 macOS 15 | ✅ 可行 | [AMD_Vanilla](https://github.com/AMD-OSX/AMD_Vanilla) 明确支持 Sequoia(15)/Tahoe(26)；Zen 4 需 IOPCIFamily 补丁；8 核 → `Force cpuid_cores_per_package` 填 `08`。1401 已内置 AMD 分支（SetupVirtualMap/DevirtualiseMmio/IOMMU off，且不套用 Intel 专属 CFG Lock） |
| 独显能否加速 | ⚠️ 中等 | RTX 4050 Laptop 在设备表内，但 **Ada 家族物理验证为 Pending，且无 RTX 4050 Laptop 成功先例**；同类 RTX 4060 Laptop 在独显直连模式下成功过 |
| 内屏能否点亮 | ⚠️ **取决于 MUX** | 内屏现挂在 780M 上（780M 在 macOS 无驱动 → 不切 MUX 则内屏全黑）。必须在 Armoury Crate 切 **独显直连/Ultimate**，让内屏走 RTX 4050 |
| 内屏刷新率 | ⚠️ 风险点 | 2560×1600@165Hz 与 issue #141/#145 同款规格，已知存在 165Hz 模式丢失/黑屏/闪烁问题 |
| 网络 | ❌ 需换硬件 | MT7922 无解 → 换 BCM94360NG（原生支持、可 AirDrop）或 Intel AX210（itlwm）。M.2 槽在右侧 NVMe 旁，可自行更换；首装阶段只能用 USB 网络共享/Type-C 网卡 |
| 声音 | ⚠️ 需调 | ALC256 → AppleALC 试 layout-id（常见 11/13/21/66/99）；喇叭功放可能需额外 fixup |
| 键盘/触控板 | ⚠️ 未知 | ASUS 多为 I2C HID，需 VoodooI2C + GPIO 引脚固定，可能需反复试；键盘背光（AURA）基本别指望 |
| 睡眠/唤醒/电源管理 | ⚠️ 差 | AMD 笔记本 + NVIDIA 驱动 + ASUS EC，是本组合最不可靠的一环，做好“只关机不睡眠”的准备 |
| 外接显示器 | ⚠️ 部分可用 | 独显 HDMI/DP 输出是驱动主打场景；但**热插拔新显示器不支持**，且可能同时黑掉内屏（#83） |
| 硬盘方案 | ✅ 可行且非破坏性 | 建议加装第二块 M.2 2280 SSD 专装 macOS，完全不动 Windows；或压缩 C: 分出 APFS 分区 |
| 系统上限 | ⚠️ 死路 | macOS 26 Tahoe 是最后支持 Intel 的版本，27 起只支持 Apple Silicon。驱动只承诺 Sequoia |
| 项目成熟度 | ❌ 很低 | 5 天、14+ 版本、123 个 open issue、作者自述“new and may not work on every PC” |

## 四、总体结论

**综合可行性：约 50–60%（“能点亮一个真正加速的 macOS 桌面”），但“能日常稳定使用”的概率低于 20%。**

### 支持尝试的理由
1. 本机具备**最关键的硬件前提**：MUX 独显直连（内屏可交给 NVIDIA 卡）+ 独显输出口 + 第二个 M.2 空位 + 安全启动已关闭。
2. 存在**拓扑几乎相同的成功先例**（#141：Ryzen + AMD 核显 + RTX 50 笔记本卡 + 同款 2560×1600@165Hz 内屏，已跑起加速桌面）。
3. 用 1401 从 Windows 一键建 OpenCore 盘，作者已专门修过 Ryzen 7000/8000/9000 的内存映射与安装卡死问题，AMD 笔记本路径是被照顾过的。
4. 成本低：一根 U 盘 + 一块可选 SSD + 一张可换的无线网卡。

### 反对的理由
1. **RTX 4050 Laptop（Ada）零验证记录**，仅有的同代笔记本正面案例（4060/4070）一半成功一半失败。
2. **内屏 165Hz 是已知重灾区**，很可能出现闪烁/黑屏/刷新率模式丢失，而笔记本没有别的内屏可用。
3. 无 MUX 时内屏必黑；即使有 MUX，驱动对 eDP 笔记本面板的支持仍属新代码（1.14.1 才撤掉一个会导致开不了机的背光固件调用）。
4. 网卡必须换硬件，声卡/触控板/睡眠都要逐个啃。
5. **安全性代价**：SIP 放宽 + AMFI 旁路 + 安全启动关闭。
6. **时代背景**：黑苹果整个生态正在终结，macOS 26 是终点；这个驱动再成功，天花板也只有一两个版本。
7. 项目 5 天大、迭代极快，随时可能因某次 macOS 小版本更新而失效（需关自动更新）。

### 建议
- **不要**把它做成你唯一的工作机；当成“第二块盘的实验项目”来做。
- 如果你只是想评估，**先做零风险验证**（见下），再决定要不要动硬盘。

## 五、如果你想验证，低风险路线

**第 0 步（零改动，先做）**
1. 先确认 `C:` 是否开了 BitLocker / 设备加密（管理员 PowerShell: `manage-bde -status C:`）。
2. Armoury Crate 里把 GPU 模式切到 **独显直连 / Ultimate**，重启确认内屏仍正常、NVIDIA 卡在设备管理器正常出现（这一步是成败关键，且必须在 Windows 下做）。
3. 下载 [1401-Windows](https://github.com/nullmoth/1401/releases) 解压，只跑 **“Check this PC / 检查本机”**（只扫描、不写盘）。它会报告内屏走哪块 GPU、BAR 布局、以及要改的 BIOS 项——这是作者给出的官方“能不能装”预检。

**第 1 步（不破坏 Windows）**
- 买一块 M.2 2280 SSD 装到第二个插槽（或至少先备份 + 压缩出 120GB 未分配空间）。
- 用 ≥16GB U 盘让 1401 生成 OpenCore + macOS 15 Sequoia 安装盘，务必**只格式化目标 SSD/分区**。
- 按 1401 提示改 BIOS：Above 4G Decoding 开、CSM 关、VT-d/SVM 视需要、Secure Boot 保持关闭。

**第 2 步（装完 macOS 后）**
- 装驱动前先确保 macOS 本身能进桌面（内屏黑就用外接显示器）。
- 用 `1401-Mac-<版本>.dmg` 装驱动，**OpenCore 盘全程插着**（Mac 端 app 不会把 OpenCore 写到内置 EFI）。
- 留好退路：OpenCore 选单里的 **1401: Remove NVIDIA driver / Start once without driver**。
- 首启会在 “PCI configuration end” 卡最多 1 分钟，属正常。

**已知坑（提前记住）**
- 从 OpenCore 选单启动 Windows 可能蓝屏（`ResizeGpuBars=13` 是全硬件生效的，见 #104）→ **Windows 从开机 F12 固件选单进**。
- 若 OpenCore 配置里残留 `disable-gpu` / 伪造 `class-code` 的 DeviceProperties，NVRM 会静默不 probe（#104 的“装好了却不加载”根因）。
- 165Hz 出问题：先降到 60Hz，或用 WindowServer plist 固定 `IODisplayModeID`（#145 的绕过法）。
- 闪烁：先加 `-nvrmnoflip`。
- macOS 自动更新要关掉，等驱动跟上再更新。
